# 촉각 기반 공 판별 알고리즘 — 전체 정리

> **Vision-Free Smart Manufacturing Cell**
> 카메라도 힘/토크 센서도 쓰지 않고, RG2 그리퍼의 **파지력 명령 + 폭 측정**만으로
> 공의 종류(테니스/야구)와 상태(무압·유압·구멍 / 하드·소프트)를 판별한다.
>
> **최종 성능: 라벨 실측 56개 전수 검증 100.0% (56/56)**

---

## 1. 한 줄 요약

> 그리퍼를 **1축 압축 시험기(compression tester)** 로 사용한다.
> 일정한 힘으로 눌렀을 때 **얼마나 들어가는가(눌림량)** 가 곧 강성이고, 강성이 곧 공의 정체다.

| 물리량 | 어떻게 얻나 | 센서 |
|---|---|---|
| 힘 (F) | 그리퍼에 **명령**한 파지력 | 불필요 (명령값이 곧 기준) |
| 변위 (Δw) | 그리퍼 폭 레지스터 **읽기** | RG2 내장 엔코더 |
| 강성 (k) | k = ΔF / Δw | 위 둘의 조합 |

## 2. 토크센서 없이 어떻게 판별하는가

### 2.1 핵심 발상

로봇에 힘/토크 센서가 없어도 문제가 되지 않는다. **힘을 측정할 필요가 없기 때문**이다.
RG2는 "이 힘으로 잡아라"라는 명령을 받으면 그 힘을 스스로 유지한다. 즉 **힘은 이미 알고 있는 상수(입력)** 이고, 우리가 관측해야 할 것은 그 힘에서 **폭이 얼마나 줄어드는가(출력)** 뿐이다.

```
   [기존 발상]  힘센서로 반력을 측정한다        → 센서 필요
   [우리 발상]  힘을 고정하고 변위를 측정한다   → 그리퍼만으로 충분
```

이것은 재료역학의 정하중 압축시험과 동일한 구조다.

```
        F(고정) ──►│  공  │◄── F(고정)
                   └──┬──┘
                 변위 Δw 측정
```

### 2.2 하드웨어 인터페이스 (Modbus TCP 직결)

ROS 드라이버를 거치지 않고 순수 소켓으로 RG2와 직접 통신한다. (`core/rg2.py`, 72줄)

| 항목 | 값 |
|---|---|
| 프로토콜 | Modbus TCP (192.168.1.1:502, unit 65) |
| 쓰기 | 주소 0 ← `[힘×10, 폭×10, 16]` (16 = GRIP 커맨드) |
| 읽기 | 주소 258부터 18워드 |
| `reg[17]` | 현재 폭 × 10 (0.1mm 분해능) |
| `reg[10]` bit0 | **busy** — 손가락이 움직이는 중 |
| `reg[10]` bit1 | **gSTA grip detected** — 물체에 막혀 멈춤 |

> 폭 분해능 **0.1mm**가 이 프로젝트의 측정 하한을 결정한다.
> 판별 경계의 마진이 0.25~0.8mm이므로 분해능 대비 **2.5~8배의 여유**를 확보한 셈이다.

## 3. 특징(Feature) 정의와 수식

### 3.1 측정 시퀀스

```
① 완전 개방 (110mm, 20N)
        ↓
② 접촉힘 F_c 로 닫기 → gSTA grip 감지 시점의 폭 = w₅   ← "자유 크기"
        ↓
③ 40N 으로 승압 → 폭이 멈출 때까지 대기 → 정착폭 = w₄₀  ← "압축된 크기"
        ↓
④ 40N 유지한 채 1.5초 더 관찰 → 추가 침하 = creep
        ↓
⑤ 개방
```

접촉힘 F_c 는 공 종류에 따라 다르다 — **테니스 5N / 야구 10N** (6절 참조).

### 3.2 특징 수식

$$
\begin{aligned}
\text{size} &= w_5 - \text{offset} && \text{(자유 상태 지름, mm)}\\[4pt]
\textbf{comp} &= w_5 - w_{40} && \textbf{(총눌림 — 판별 핵심, mm)}\\[4pt]
\text{creep} &= w_{40} - w_{40}(t{+}1.5\text{s}) && \text{(점탄성 표류, mm)}\\[4pt]
\text{strain} &= \frac{\text{comp}}{\text{size}} && \text{(변형률, 무차원)}\\[4pt]
k_{\text{eff}} &= \frac{F_{40} - F_c}{\text{comp}} && \text{(등가 강성, N/mm)}
\end{aligned}
$$

**comp(총눌림)가 판별의 핵심 특징**이다. 물리적으로:

$$
\text{comp} \;\propto\; \frac{1}{k} \;=\; \frac{1}{k_{\text{내부공기압}} + k_{\text{고무껍질}}}
$$

- 공기압이 정상이면 → 내부 압력이 버팀 → k 큼 → **comp 작음**
- 구멍이 나서 공기가 새면 → 껍질만 버팀 → k 작음 → **comp 큼**
- 애초에 공기가 없는 단단한 고무공(무압)은 → 재질 자체가 단단 → **comp 가장 작음**

### 3.3 왜 고압 구간(40N)에서 재는가

결함(공기 누출)은 **높은 힘에서만 드러난다.** 저압에서는 껍질의 탄성이 지배해 정상공과 불량공이 비슷하게 눌린다. 힘을 올릴수록 내부 공기압이 버티는 정상공과, 버틸 것이 없는 불량공의 차이가 벌어진다.

```
눌림
 ▲
 │                                  ╱ 구멍(불량)
 │                            ╱────
 │                      ╱────       ← 여기서 격차 최대
 │                ╱────  ╱─────────  유압(정상)
 │          ╱────  ╱────
 │    ╱────  ╱───────────────────    무압(딱딱)
 └────┬──────────────┬──────────► 힘
     5N            40N
   구분 거의 안 됨   명확히 분리
```

## 4. 판정 알고리즘 (캐스케이드 구조)

### 4.1 전체 흐름

```
                  측정 완료 (size, comp, creep, w40)
                            │
              ┌─────────────▼─────────────┐
              │  게이트 0 : 이상값 차단     │  ← 5절 예외처리
              │  size ≥ 80 → 잘못 잡힘     │
              │  comp > 10 → 접촉감지 오류  │
              └─────────────┬─────────────┘
                            │ 정상
              ┌─────────────▼─────────────┐
              │  게이트 1 : 공 종류 분리    │
              │  size < 67.8 ? 테니스 : 야구│
              └──────┬──────────────┬─────┘
                     │ 테니스        │ 야구
          ┌──────────▼───────┐  ┌───▼──────────────┐
          │ ① comp ≤ 3.6 ?   │  │ comp ≤ 2.55 ?    │
          │   → 🔵 무압(포장) │  │  → 🟡 하드        │
          └──────────┬───────┘  │  → 🟠 소프트      │
                     │ 아니오    └──────────────────┘
          ┌──────────▼───────┐
          │ ② comp ≤ 5.5 ?   │
          │   → 🟢 유압(포장) │
          │   → 🔴 구멍(불량) │
          └──────────────────┘
```

### 4.2 현재 적용 중인 임계값 (자동계산 결과, `ball_thresholds.json`)

| 관문 | 특징 | 경계 | 방향 |
|---|---|---|---|
| 공 종류 분리 | size | **67.8 mm** | 미만=테니스 |
| 테니스 무압/그외 | comp | **3.6 mm** | 이하=무압 |
| 테니스 유압/구멍 | comp | **5.5 mm** | 이하=유압 |
| 야구 하드/소프트 | comp | **2.55 mm** | 이하=하드 |
| 오파지 차단 | size | **80.0 mm** | 이상=미검출 |
| 물리 상한 | comp | **10.0 mm** | 초과=측정오류 |

### 4.3 캐스케이드의 중요한 설계 결정

**1단계 관문은 `무압 vs (유압 + 구멍)` 으로 학습한다.** — 이것이 가장 중요한 안전 설계다.

만약 `무압 vs 유압` 만으로 경계를 학습하면, 그 경계는 구멍공의 존재를 모른다. 캐스케이드 구조상 1단계를 통과한 공만 2단계로 가므로, **구멍공이 1단계에서 무압으로 분류되면 그대로 포장되어 출하된다.**

> 실측 사고: 구멍공 8개 중 **6개가 무압으로 유출**됐다.
> → 1단계 학습 대상을 "나머지 전체"로 바꿔 해결. (`core/gripper.py:288`)

**불량 유출은 최악의 오류**이므로, 모든 경계는 불량 쪽에 보수적으로 잡는 것을 원칙으로 했다.

## 5. 미접촉 / 예외 판단 알고리즘

"공을 못 잡았다"를 정확히 아는 것은 판별만큼 중요하다. 공이 없는데 판정하면 허공의 값으로 등급이 매겨지고, 그 공은 존재하지도 않는 채로 포장 카운트에 들어간다.

### 5.1 5중 게이트

| # | 조건 | 판정 | 근거 |
|---|---|---|---|
| ① | gSTA grip 플래그 미검출 | 물체 없음 | 손가락이 끝까지 닫힘 |
| ② | `w₅ < 15mm` (min_ball_width) | 물체 없음 | 실공 최소 63mm — 안전 여유 4배 |
| ③ | `size ≥ 80mm` (misgrip_min) | 잘못 잡힘 | 실공 최대 77mm, 오파지 실측 ≈86mm |
| ④ | `comp > 10mm` (comp_max_sane) | 접촉감지 오류 | 물리적으로 불가능한 눌림 |
| ⑤ | `w₄₀ < 30mm` (min_hold_width) | **이송 중 놓침** | 40N에서 거의 닫혔다 = 공이 빠져나감 |

**게이트 ⑤가 특히 중요하다.** 잡았다가 미끄러져 빠지면 폭이 급격히 줄어드는데, 이때 comp가 거대해져서 **"매우 물렁한 공 = 불량"으로 오판**된다. 놓친 것을 불량으로 기록하면 데이터까지 오염되므로, 분류 자체를 하지 않고 재시도로 보낸다.

### 5.2 재시도 계층 (3단 방어)

```
[1단] 접촉 감지 실패
      → 완전 개방 → 재접근  (measure_retry = 2회, 총 3회 시도)

[2단] 3회 모두 실패
      → flow_code = 'misgrip' 반환, 판정 생략

[3단] 사이클 레벨 (sequences/order.py:553)
      → 잡은 것을 원래 슬롯에 되돌려 놓고
      → 안전 경유지(P5)로 복귀 → status='retry' → 다음 사이클 재시도
      (공이 아예 없으면 status='empty' → 슬롯 비었음을 사용자에게 알림)
```

로봇이 **혼자 헛돌지 않고 항상 안전 상태로 되돌아온 뒤** 다시 시도하는 것이 핵심이다.

## 6. 야구공 정렬 사이클 (Align Cycle)

### 6.1 문제 — 야구공에서만 접촉 감지가 계속 빗나갔다

| | 테니스공 | 야구공 |
|---|---|---|
| 무게 | 58 g | **145 g (2.5배)** |
| 표면 | 펠트(마찰 큼) | 가죽(미끄러움) |
| 5N 접촉 결과 | 정상 | **빗나감** |

**원인:** 접촉힘 5N은 145g의 야구공을 그리퍼 중앙으로 **밀어낼 힘이 안 된다.**
공이 한쪽으로 치우친 채 손가락에 물리면, 지름이 아니라 **현(chord)** 을 재게 된다.

> 실측 오차: w₅ 가 정상 70~73mm 대신 **75~77mm 로 부풀어 기록**됐다.
> size가 부풀면 comp까지 연쇄로 부풀어 → **하드를 소프트로 오판**.

### 6.2 왜 "힘만 올리기"로는 해결이 안 되는가

이미 빗나가게 물린 상태에서 힘만 올리면, **잘못된 자세를 더 세게 조일 뿐**이다. 공은 이미 손가락에 갇혀 있어 중앙으로 굴러갈 자유도가 없다.

→ **반드시 한 번 놓아주고 다시 잡아야 한다.**

### 6.3 해결 — 4단계 정렬 사이클

```
   ① 1차 5N 접촉 → 크기 측정 → size ≥ 67.8 이면 "야구공"으로 판단
              ↓
   ② 40N 으로 꽉 잡기 (align_force, 0.8초 유지)
       └ 강한 힘으로 공을 그리퍼 정중앙으로 강제 정렬
              ↓
   ③ 완전 개방 → 1.8초 형상 회복 대기 (align_recover)
       └ 눌렸던 고무가 점탄성으로 원래 지름을 되찾는 시간
              ↓
   ④ 10N 으로 재접근 → 이 값으로 최종 측정
       └ 정렬된 상태 + 충분한 밀어내기 힘
```

### 6.4 접촉힘 10N의 근거

세게 잡을수록 정렬은 잘 되지만, 접촉 시점에서 이미 공이 눌려버려 **판별 신호(comp)를 잃는다.** 접촉힘별 신호 손실을 실측했다:

| 접촉힘 | comp 신호 손실 | 판정 |
|---|---|---|
| 5 N | 0 % | 정렬 실패 ✗ |
| **10 N** | **6 %** | **채택 ✓** |
| 12 N | 20 % | 손실 과다 |
| 20 N | 66 % | 판별 불가 ✗ |

> 10N은 "정렬은 되면서 신호는 살아있는" 지점이다.

### 6.5 접촉힘이 다르면 데이터도 분리해야 한다

야구공의 comp는 **10N→40N** 구간, 테니스공은 **5N→40N** 구간이다. 척도가 다르므로 섞이면 경계가 오염된다. 그래서 CSV에 `contact_N` 열을 두고, 임계값 자동계산 시 **현재 설정과 접촉힘이 다른 행은 자동 제외**한다. (`core/gripper.py:222`)

> "조용히 틀리는 것이 최악"이라는 원칙에 따라, 제외된 행 수를 화면에 반드시 표시한다.

## 7. 접촉 감지 알고리즘 (거짓 접촉 제거)

gSTA bit1(grip detected)을 그냥 읽으면 **거짓 양성**이 대량 발생했다. 대표 증상이 "허공 40N 슬램" — 아무것도 없는데 잡았다고 판단하고 40N으로 닫아버리는 현상이다.

### 7.1 3중 조건 (OnRobot 공식 절차 준수)

```python
접촉 인정 = (busy == 0)          # ① 정지 상태에서만 판독
          AND (gSTA bit1 == 1)   # ② 파지 플래그
          AND fresh_motion       # ③ '이번 명령'으로 움직였다는 증거
```

**① 정지 상태 판독**
grip detected의 정의는 "이동이 물체에 막혀 멈췄다"이다. 움직이는 중(busy=1)에 읽으면 이전 명령의 잔류 플래그나 과도 상태를 접촉으로 오인한다.

**② 명령 전 idle 대기**
이전 모션이 끝나기 전에 새 닫기 명령을 보내면 **방향 전환 스톨**이 발생하고, 이것이 파지로 오인된다. 그래서 명령 전에 busy=0을 최대 2초까지 기다린다.

**③ fresh_motion — 잔류 플래그 차단**
```
fresh_motion = (이번 명령 후 busy 상승을 관측) 
               OR (시작폭 − 현재폭 ≥ 2.0mm)
```
개방 직후 남아 있는 **이전 사이클의 gSTA bit1**을 새 공의 접촉으로 오인하는 것을 막는다.
> 임계값 2.0mm의 근거: 0.5mm는 노이즈 범위라 잔류 플래그가 그대로 통과했다. (`contact_fresh_travel`)

## 8. 임계값 자동설정 알고리즘

사람이 숫자를 손으로 정하지 않는다. **라벨링된 실측 데이터로부터 경계를 유도**한다.

### 8.1 전체 파이프라인

```
[학습 모드 사이클]
  로봇이 공을 집어 측정 → 판정하지 않고 공을 잡은 채 대기
        ↓
  작업자가 화면에서 정답 라벨 클릭 (무압/유압/구멍/하드/소프트)
        ↓
  ball_measurements_final.csv 에 (size, comp, creep, w40, contact_N, label) 저장
        ↓
  공을 원래 슬롯에 반납 → 다음 공  ← 반복
        ↓
[임계값 자동계산 버튼]
  → compute_thresholds() → ball_thresholds.json 저장 → 즉시 적용
```

### 8.2 핵심 알고리즘 — `best_split()`

두 클래스 A, B를 나누는 **최적 경계**를 찾는다. (`core/gripper.py:252`)

**단계 1 — 후보 경계 생성**
두 클래스의 모든 실측값을 합쳐 정렬하고, **인접한 값 사이의 중점**을 전부 후보로 삼는다.

$$
V = \text{sort}(A \cup B), \qquad
C = \left\{ \frac{v_i + v_{i+1}}{2} \;\middle|\; i = 1 \dots |V|-1 \right\}
$$

**단계 2 — 각 후보의 정확도와 마진 계산**

$$
\text{acc}(c) = \frac{\bigl|\{a \in A : a \le c\}\bigr| + \bigl|\{b \in B : b > c\}\bigr|}{|A| + |B|}
$$

$$
\text{margin}(c) = \min_{v \in V} |v - c|
$$

**단계 3 — 사전식 순서로 최적 선택**

$$
c^{*} = \arg\max_{c \in C} \; \bigl(\text{acc}(c),\; \text{margin}(c)\bigr)
$$

즉 **정확도가 최우선이고, 동률이면 여유(마진)가 가장 큰 곳**을 고른다.

**단계 4 — 특징 선택**
후보 특징 `{size, comp}` 각각에 대해 위를 수행하고, **분리도(정확도)가 가장 높은 특징**을 그 관문의 판정 기준으로 채택한다. 방향(이하가 A인지 초과가 A인지)도 중앙값 비교로 자동 결정한다.

$$
\text{direction} = \begin{cases}
A\text{가 아래쪽} & \text{if } \text{median}(A) < \text{median}(B)\\
A\text{가 위쪽} & \text{otherwise}
\end{cases}
$$

### 8.3 왜 "중앙값 중점"을 쓰지 않는가

초기 버전은 단순히 두 그룹 중앙값의 중점을 썼다.

$$
c_{\text{old}} = \frac{\text{median}(A) + \text{median}(B)}{2}
$$

이 방식은 **두 분포가 가깝게 붙어 있을 때 경계가 표본 안쪽으로 파고든다.** 중앙값은 분포의 중심이지 경계가 아니기 때문이다. 실제로 무압/유압에서 오분류가 발생했다.

```
   중앙값 중점 방식                  전수 스캔 방식
   A: ●●●●●●              B: ○○○○   A: ●●●●●●          B: ○○○○
        └─ med          med ─┘            ↑
             ╲          ╱                 └ 여기 (빈 구간 한복판)
              ╲        ╱
               중점 = 표본을 관통!         마진 최대 = 오분류 0
```

### 8.4 종류 경계와 오파지 경계

$$
\text{type\_split} = \frac{\text{median}(\text{size}_{\text{tennis}}) + \text{median}(\text{size}_{\text{baseball}})}{2}
= \frac{64.60 + 70.85}{2} \approx 67.7
$$

$$
\text{misgrip\_min} = \frac{\max(\text{size}_{\text{실제공}}) + \min(\text{size}_{\text{오파지}})}{2}
$$

종류 경계는 두 그룹이 3.5mm나 떨어져 있어(테니스 최대 65.6 / 야구 최소 69.1) 중점 방식으로 충분하다.

### 8.5 왜 특징 후보를 2개(size, comp)로 제한했는가 — 다중비교 문제

한때 후보에 `w40`, `strain`, `creep`까지 넣었다. 표본이 적을 때는 이들이 **우연히** 100% 분리를 달성해 선택되곤 했지만, 표본이 늘자 무너졌다.

> 실측 붕괴: w40 채택 시 야구 **100% → 62%**, 테니스 **100% → 67%**

후보를 늘릴수록 "우연한 승자"가 뽑힐 확률만 커진다(다중비교, multiple comparisons). 그래서 **물리적 근거가 명확한 두 특징만** 남겼다. 이것은 통계적 과적합을 구조적으로 차단한 설계다.

### 9.2 특징 선택의 실증 — 왜 comp인가

동일 데이터로 세 특징의 분리 성능을 비교했다.

| 관문 | **눌림(comp)** | 크기(size) | 40N폭(w40) |
|---|---|---|---|

comp만이 **세 관문 전부에서 100%** 를 달성했다. 자동계산이 세 관문 모두 comp를 선택한 것은 이 실증의 결과다.

### 9.3 측정 재현성을 확보한 6가지 기법

100%는 알고리즘이 아니라 **측정 품질**에서 나왔다. 재현성을 깨뜨리는 요인을 하나씩 제거했다.

**① 정착 대기 (settle) — 고정 대기의 폐기**
고무는 점탄성이라 힘을 준 직후에도 계속 눌린다. 고정 시간 대기는 "아직 눌리는 중"의 값을 읽어 편차를 만든다.
→ **폭 변화 < 0.15mm가 3회 연속**될 때까지 대기하도록 변경. 단, "시작폭보다 0.3mm 이상 실제로 눌린 뒤"에만 정착을 인정해서, 아직 닿지도 않았는데 멈춤으로 오인하는 것을 막았다.

**② 크립을 comp에서 분리**
초기에는 10→20→30→40N 계단식으로 올렸는데, 각 단계의 정착 대기 동안 크립이 발생해 **comp에 섞여 들어갔다.** 두 물리량이 뒤엉켜 재현성이 무너졌다.
→ **접촉힘에서 40N으로 직행**하고, 크립은 그 뒤 1.5초 동안 **따로** 측정. comp = 순수 탄성압축, creep = 점탄성 표류로 분리했다.

**③ 히스테리시스 회피**
40N에서 힘을 뺐다가 다시 접촉폭을 읽으면, 점탄성 히스테리시스 때문에 값이 작아진다.
→ **처음 접촉에서 얻은 w₅를 기억해 끝까지 기준으로 사용.** 다시 읽지 않는다.

**④ 사이클과 측정도구의 완전 일치**
자동 사이클은 원래 "40N 원샷 슬램"으로 잡았는데, 급격한 압축은 점탄성 오버슛을 일으켜 comp를 부풀렸다. 그 결과 **수동 측정도구와 자동 사이클의 판정이 서로 달랐다.**
→ 사이클도 측정도구와 **동일한 정착 절차**를 쓰도록 통일. 학습 데이터와 운영 판정이 같은 척도가 되었다.

**⑤ 거짓 접촉 제거** (7절)
허공을 잡고 40N으로 닫는 오작동을 3중 조건으로 차단.

**⑥ 야구공 정렬 사이클** (6절)
치우쳐 물린 공의 현(chord) 측정을 정렬 후 재측정으로 해결.

### 9.4 안전 설계 — "틀리더라도 안전한 방향으로"

- **불량 유출 0 우선**: 경계는 항상 불량 쪽에 보수적으로. 정상을 불량으로 보내는 것(비용: 공 하나)보다 불량을 포장하는 것(비용: 고객 클레임)이 훨씬 나쁘다.
- **애매하면 판정하지 않는다**: 5중 게이트 중 하나라도 걸리면 등급을 매기지 않고 재시도로 보낸다. 억지 판정을 하지 않는다.
- **조용한 실패 금지**: 접촉힘 불일치로 제외된 데이터, 분포 겹침 경고 등을 전부 화면에 표시한다.

## 11. 요약 — 이 프로젝트의 기술적 기여

1. **센서 없는 물성 측정**: 힘/토크 센서 없이 그리퍼의 힘 명령 + 폭 읽기만으로 강성을 정량화했다.
2. **물리 기반 특징 설계**: comp(총눌림)라는 단일 특징이 공기압의 유무를 직접 반영한다는 것을 실증했다.
3. **데이터 주도 임계값**: 사람이 숫자를 정하지 않고, 라벨 데이터에서 정확도·마진 최대 경계를 유도한다.
4. **과적합 방지 설계**: 다중비교 문제를 인식하고 특징 후보를 물리적 근거로 제한했다.
5. **안전 우선 캐스케이드**: 불량 유출을 구조적으로 차단하고, 애매하면 판정하지 않는다.
6. **재현성 공학**: 점탄성·히스테리시스·잔류 플래그·정렬 오차를 하나씩 제거해 100%에 도달했다.

> **최종 성능: 5클래스 56샘플 전수 검증 100.0%, 모든 클래스 간 물리적 분리 확보**
