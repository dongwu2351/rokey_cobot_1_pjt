# 순응제어 — 뚜껑을 '힘으로 밀지 않고' 안착·체결하는 방법

> **한 줄 요약**
> 로봇을 **축마다 다른 강성**으로 만들어, 위치는 잡되 접촉은 흘려보낸다.
> X/Y는 단단하게(안 밀림), Z와 기울기는 부드럽게(정렬 흡수) — 그래서 뚜껑이 억지로가 아니라 **자연스럽게 앉는다.**

## 1. 왜 순응제어가 필요한가

뚜껑을 통에 닫는 동작은 **나사를 조이는 것과 같다.**

```
    그리퍼가 잡은 뚜껑
          │
          ▼  내려서
    ┌──────────┐
    │   통 입구  │   ← 여기에 정확히 맞춰 앉히고, 돌려서 잠근다
    └──────────┘
```

### 강성 제어(기본 모드)로 하면 생기는 문제

로봇은 기본적으로 **매우 단단하다(stiff)**. 명령한 좌표로 **무슨 수를 써서라도** 간다.

| 상황 | 강성 제어의 결과 |
|---|---|
| 티칭 좌표가 0.5mm 어긋남 | 뚜껑 모서리가 통 입구에 걸린 채 **억지로 밀어 넣음** |
| 통이 살짝 기울어 있음 | 정렬 안 된 채 **찍어 누름** → 나사산 뭉개짐 |
| 뚜껑이 그리퍼에 미세하게 비스듬히 물림 | 그대로 밀어 **통 파손 또는 충돌 알람** |

**근본 원인**: 실제 조립은 항상 **µm~mm 단위 오차**가 있는데, 강성 제어는 그 오차를 흡수할 방법이 없다.
힘이 갈 곳이 없으니 **부품이 부서지거나 로봇이 충돌로 판단해 멈춘다.**

### 순응제어의 해법

로봇을 **선택적으로 무르게** 만든다. 접촉이 생기면 그 방향으로 **살짝 물러나** 정렬이 저절로 맞는다.

```
강성 제어:  뚜껑 ──▶│ 통    "안 들어가? 더 세게!"  → 파손
순응 제어:  뚜껑 ~~▶│ 통    "걸렸네, 살짝 비켜서"  → 안착
```

## 2. 순응제어란 — 가상 스프링

Task Compliance Control은 로봇 **툴 끝(TCP)에 6개의 가상 스프링**을 다는 것이다.

```
        Z (병진)
        ↕ 스프링
   X ↔ ●━━━━━ TCP
        ↕
        RX/RY/RZ (회전) 스프링
```

각 축의 **강성(stiffness)** 을 지정하면, 그 축으로 외력이 걸릴 때
`변위 = 힘 / 강성` 만큼 밀린다.

| 강성 | 거동 |
|---|---|
| **높음** (예 3000) | 거의 안 밀림 — 강성 제어에 가까움 |
| **낮음** (예 150) | 잘 밀림 — 접촉을 부드럽게 흡수 |

### ROS 서비스 정의

`dsr_msgs2/srv/TaskComplianceCtrl.srv`:

```
float64[6] stx    # 병진 강성 3개 + 회전 강성 3개
                  # default [3000, 3000, 3000, 200, 200, 200]
int8       ref    # 기준 좌표계
float64    time   # 강성 전이 시간 [0 ~ 1.0 s], 그 시간 동안 선형 전환
---
bool       success
```

`stx = [X, Y, Z, RX, RY, RZ]`
- 앞 3개: **병진 강성** (단위 N/m 계열)
- 뒤 3개: **회전 강성** (단위 Nm/rad 계열)

`time`은 **급격한 강성 변화로 로봇이 튀지 않게** 하는 전이 시간이다.

## 3. 강성값 설계 — 축마다 다르게

여기가 이 구현의 **핵심 설계**다. 모든 축을 무르게 하면 뚜껑이 제자리를 못 잡는다.

```python
def comp_on():
    rq = ctx.TaskComplianceCtrl.Request()
    # 나사 체결용: X/Y·RZ는 단단(위치 유지+회전 토크 전달), Z·RX/RY는 부드럽게(안착·정렬 흡수)
    rq.stx = [2000.0, 2000.0, 500.0, 150.0, 150.0, 300.0]
    rq.ref = 0
    rq.time = 0.5
    r = ctx.call(ctx.ccomp_on, rq, cto=2.0)
    if r is None or not getattr(r, 'success', False):
        raise RuntimeError('순응제어 ON 실패')
    in_comp[0] = True
    time.sleep(0.6)
```

### 각 축을 그렇게 정한 이유

| 축 | 값 | 기본값 | 성격 | 왜 |
|---|---|---|---|---|
| **X** | 2000 | 3000 | 단단 | 뚜껑이 **옆으로 밀리면 안 됨** — 통 입구를 벗어남 |
| **Y** | 2000 | 3000 | 단단 | 위와 동일 |
| **Z** | **500** | 3000 | **부드럽게** | 내려앉는 방향. **접촉 하중을 흡수**해야 함 ← 가장 중요 |
| **RX** | **150** | 200 | **부드럽게** | 뚜껑이 살짝 기울어도 **평면에 맞춰 눕도록** |
| **RY** | **150** | 200 | **부드럽게** | 위와 동일 |
| **RZ** | 300 | 200 | 단단 | **회전 토크를 뚜껑에 전달**해야 잠긴다 ← 여기만 기본보다 높임 |

### 설계 논리를 한 문장으로

> **"위치(X/Y)는 지키고, 눌림(Z)과 기울기(RX/RY)는 흘려보내고, 회전(RZ)은 전달한다."**

```
        ↓ Z: 500 (무름)          ← 접촉하면 물러남
        │
   X:2000 ●━━━━━━━ Y:2000       ← 옆으로 안 밀림
   (단단)  │        (단단)
          RZ:300 ⟳               ← 돌리는 힘은 그대로 전달 (기본 200보다 높임)
        RX/RY:150 (무름)         ← 기울기 자동 정렬
```

**RZ만 기본값보다 높인 것**이 포인트다. 다른 축은 다 낮추면서 회전만 올린 이유는,
**나사를 조이려면 회전 토크가 손실 없이 전달되어야** 하기 때문이다.
RZ까지 물렁하면 로봇만 헛돌고 뚜껑은 안 잠긴다.

## 4. 적용 구간 — 뚜껑 닫기 4단계

순응제어는 **뚜껑 닫기(`run_lid('close')`)의 안착·체결 구간에서만** 켠다.

```
P5 → P9 → P24 (뚜껑 잡기 0mm/10N)
   │
   ▼  블렌딩 이송 (강성 제어)
P5 → P21 (하강 직전 위치)
   │
   ▼  ★comp_on()  강성 [2000,2000,500,150,150,300]
┌──────────────────────────────────────────┐
│ ③ P21 → P22   순수 Z 하강 (26.8mm, 8mm/s) │  ← 안착
│ ④ P22 → P23   C축 회전 −41° (12°/s)       │  ← 잠금
└──────────────────────────────────────────┘
   │
   ▼  ★comp_off()  강체 복귀
⑤ 무게 측정 (영점 → 재파지 → +100mm → 계산)
   │
   ▼
−90mm 하강 → 개방 → P21 → P5
```

### 실행 코드

```python
msg('🧢 ③ 순응제어 ON → P10 안착(직선 하강 · 접촉 허용)')
comp_on()
try:
    _v_desc = cfg.move_vel('lid_comp_descend')        # 8 mm/s
    movel_abs(mount_px, vmm=_v_desc, vdeg=10.0)       # 순수 Z 하강

    msg('🧢 ④ 회전 잠금(P10→P11 · C축 −41°)')
    _v_rot = cfg.move_vel('lid_comp_rotate')          # 12 deg/s
    movel_abs(locked_px, vmm=_v_desc, vdeg=_v_rot)    # C축 회전 체결(순응 유지)
finally:
    comp_off()                                        # ★반드시 해제
```

> **`try / finally`가 중요한 이유**: 중간에 어떤 예외가 나도 **순응제어는 반드시 꺼진다.**
> 켜진 채로 남으면 이후 모든 이동이 물렁해져 위치 정밀도가 무너지고, 무게 측정도 틀어진다.

### 왜 느린가 — 8 mm/s · 12 deg/s

| 이동 | 속도 | 이유 |
|---|---|---|
| 순응 하강 | **8 mm/s** | 접촉을 **감지하고 흡수할 시간**이 필요. 빠르면 순응이 반응하기 전에 충격이 전달됨 |
| 회전 잠금 | **12 deg/s** | 나사산이 물리며 정렬될 시간 |

이 두 구간은 **전 공정에서 유일하게 느린 곳**이다(나머지는 60°/s 최대).
속도 탭에서 `lid_comp_descend` / `lid_comp_rotate`로 개별 조절할 수 있다.

## 5. 제약 ① 순응 중에는 MoveJ 금지

```python
# ★순응제어 중 movej는 두산 제약으로 거부됨 → 순응 구간은 movel(posx)로만 이동
```

**두산 컨트롤러 제약**: 순응제어가 켜진 상태에서 `movej`(관절 이동)를 호출하면 **거부된다.**

순응제어는 **태스크 공간(TCP 기준 직교좌표)** 에서 정의되는 개념이라
관절 공간 명령과 개념이 맞지 않기 때문이다.

### 그래서 `movel_abs()` — 절대 posx 직선이동

```python
def movel_abs(posx, vmm=12.0, vdeg=15.0, cto=30.0):
    """절대 posx로 직선(태스크) 이동 — ★순응제어 중 movej는 거부되므로 순응 구간은 이것만 사용."""
    chk()
    ctx.motion_active.set()
    try:
        rq = ctx.MoveLine.Request()
        rq.pos = [float(x) for x in posx]         # 절대 좌표 (x,y,z,rx,ry,rz)
        rq.vel = [float(vmm), float(vdeg)]        # [병진 mm/s, 회전 deg/s]
        rq.acc = [float(vmm) * 2.0, float(vdeg) * 2.0]
        rq.time = 0.0; rq.radius = 0.0; rq.ref = 0
        rq.mode = 0                               # 절대
        rq.blend_type = 0; rq.sync_type = 0       # ★SYNC — 도착까지 블로킹
        res = ctx.call(ctx.cml, rq, cto=cto)
        ...
```

### 이것이 웨이포인트 요구사항을 바꾼다

일반 이동은 `posj`(관절각)만 있으면 되지만, **순응 구간은 `posx`(직교좌표)가 필요하다.**

```python
mount_wp  = _find_named_wp(wps, cfg.LID_WP_NAMES['lid_mount'])
locked_wp = _find_named_wp(wps, cfg.LID_WP_NAMES['lid_mount_locked'])
mount_px  = (mount_wp or {}).get('posx')
locked_px = (locked_wp or {}).get('posx')
if not (mount_px and locked_px and len(mount_px) == 6 and len(locked_px) == 6):
    raise RuntimeError('P10/P11의 posx 미티칭 — 순응 하강 불가(재티칭 필요)')
```

> ⚠️ **P22/P23(구 P10/P11)은 반드시 `posx`까지 티칭되어 있어야 한다.**
> `_find_named_wp()`가 `posj`만이 아니라 **웨이포인트 dict 전체**를 반환하는 이유가 이것이다.

## 6. 제약 ② 하강량은 Z만 대체

### 문제

티칭한 P22/P23 좌표를 그대로 쓰면, 티칭 당시의 **높이에 고정**된다.
통 높이가 조금 달라지거나 하강량을 조절하고 싶을 때 **재티칭해야** 한다.

### 해결 — X·Y·자세는 티칭값, Z만 계산

```python
# ★하강량을 설정으로 지정하면 P12 기준으로 그 값만큼만 내려간다.
#   티칭 좌표(T10/T11)는 X·Y·자세를 그대로 쓰고 Z만 대체 → 순수 Z 하강 유지.
#   회전 잠금(T11)도 같은 높이에서 이뤄져야 하므로 함께 맞춘다.
_dz = cfg.GRIPPER.get('lid_descend_mm')          # 26.8 mm
pre_wp = _find_named_wp(wps, cfg.LID_WP_NAMES['lid_mount_pre'])
pre_px = (pre_wp or {}).get('posx')
if _dz is not None and pre_px and len(pre_px) == 6:
    _z = float(pre_px[2]) - float(_dz)           # P21 높이에서 26.8mm 아래
    mount_px  = list(mount_px);  mount_px[2]  = _z
    locked_px = list(locked_px); locked_px[2] = _z    # ★회전도 같은 높이에서
    msg(f'🧢 순응 하강량 {float(_dz):.1f}mm (Z {pre_px[2]:.1f} → {_z:.1f})')
```

**두 가지를 동시에 만족한다:**

| | |
|---|---|
| **순수 Z 하강** | X·Y·자세가 P21과 동일 → 옆으로 안 새고 똑바로 내려감 |
| **조절 가능** | `lid_descend_mm` 값만 바꾸면 재티칭 없이 하강량 변경 |

**회전 잠금(P23)도 같은 Z로 맞추는 이유**: 뚜껑이 앉은 높이에서 그대로 돌아야 한다.
높이가 다르면 돌리면서 뚜껑이 들리거나 더 눌린다.

## 7. 제약 ③ 무게 측정 전 반드시 해제

```python
finally:
    comp_off()      # 들어올리기 전 강체 복귀(무게 정확)
```

순응제어는 **힘을 흡수하도록** 설계된 모드다.
켜진 채로 통을 들면 로봇이 부드럽게 따라가며 힘을 흘려보내
**`Fz`가 실제 하중보다 작게** 측정된다.

```
순응 ON  상태로 들기 →  Fz 가 하중의 일부만 반영  →  무게 과소 측정
순응 OFF 상태로 들기 →  Fz 가 하중 전체를 반영    →  정확  ✅
```

자세한 무게 알고리즘은 **[WEIGHT_SENSING.md](WEIGHT_SENSING.md)** 참조.

## 8. 제약 ④ 자동복구 금지 구역

외력 자동복구는 작업 전 과정에 적용되지만, **순응 구간만은 의도적으로 제외**했다.

```python
st = robot_state()
# ★순응 구간은 자동복구하지 않는다: 안전정지로 순응이 풀린 뒤 같은 목표로 다시
#   보내면 뚜껑을 '강성'으로 밀어 넣는다. 작업자가 확인하는 편이 안전하다.
if in_comp[0]:
    if st in (3, 5, 8, 9, 10):
        raise RuntimeError(
            f'순응 구간(뚜껑 안착) 이동 중 안전정지(state={st}) — '
            '자동복구 금지 구간, 뚜껑 상태 확인 후 수동 재시작')
else:
    trip.check(st)
```

### 왜 위험한가

```
순응제어 ON  →  로봇이 부드럽게 뚜껑을 안착시키는 중
      │
      ▼  외력 또는 과부하로 보호정지
안전정지 발생  →  ★순응제어가 함께 풀린다
      │
      ▼  자동복구가 서보를 켜고 같은 목표로 MoveL 재전송
로봇이 강성(stiff) 상태로 뚜껑을 밀어 넣음  →  뚜껑·통 파손
```

**순응이 풀린 것을 모른 채 같은 명령을 다시 보내는 것**이 문제의 핵심이다.
복구 전에 순응을 다시 켜는 방법도 있지만, 그 시점에 뚜껑이 어느 상태인지
(반쯤 앉았는지, 걸렸는지, 빠졌는지) 알 수 없어 **작업자 확인이 안전하다.**

### 순응 상태 추적

```python
in_comp = [False]      # 순응제어 활성 여부 — 이 구간은 자동복구 대상에서 뺀다

def comp_on():
    ...
    in_comp[0] = True

def comp_off():
    ...
    in_comp[0] = False
```

리스트로 두는 이유는 **클로저 안에서 값을 바꿔야** 하기 때문이다(정수는 불변).

자세한 자동복구 구조는 **[AUTO_RECOVERY.md](AUTO_RECOVERY.md)** 참조.
