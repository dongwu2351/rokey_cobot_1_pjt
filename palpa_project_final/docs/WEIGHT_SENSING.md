## 1. 왜 무게를 재는가

로봇은 **카메라 없이** 공을 포장한다. 포장이 끝났을 때 다음을 확인할 방법이 없다:

- 공이 정말 통 안에 들어갔는가? (놓다가 튕겨 나갔을 수 있다)
- 몇 개가 들어갔는가?
- 뚜껑이 제대로 닫혔는가?

**무게가 유일한 물리적 증거**다. 뚜껑을 닫은 뒤 통을 들어올려 무게를 재면,
공 개수 × 공 무게 + 통 무게가 맞는지 확인할 수 있다.

```
테니스공 ≈ 58 g   ·   야구공 ≈ 145 g
→ 개수가 하나만 달라도 수십 g 차이 → 충분히 구분 가능
```

## 2. 왜 절대값을 못 쓰는가

로봇 툴에 걸리는 힘 `Fz`를 그냥 읽으면 무게가 나올 것 같지만, 실제로는 **오차 덩어리**다.

| 오차원 | 크기 | 왜 생기나 |
|---|---|---|
| **그리퍼 자중** | 약 1 kg | RG2 자체 무게가 항상 걸림 |
| **payload/TCP 설정 오차** | 수십~수백 g | 펜던트에 등록한 공구 무게·무게중심이 실제와 다름 |
| **자세별 중력보상 오차** | **자세마다 다름** | 컨트롤러가 자세에 따라 중력을 보상하는데, 그 모델 오차가 자세마다 달라짐 |
| **센서 드리프트** | 시간에 따라 변동 | 온도·사용 시간 |

특히 **세 번째가 치명적**이다. 로봇 자세가 바뀌면 오차 자체가 바뀌므로,
"어떤 자세에서 잰 절대값"을 기준으로 삼을 수가 없다.

## 3. 핵심 원리 — 차분 측정

### 발상

오차들이 **자세에만 의존**한다면, **자세를 안 바꾸고** 두 번 재면 어떨까?

```
Fz₀ = W_그리퍼 + E_payload + E_중력보상(자세)                 ← 들기 전
Fz₁ = W_그리퍼 + E_payload + E_중력보상(자세) + W_통          ← 들어올린 뒤
──────────────────────────────────────────────────────────
Fz₁ − Fz₀ = W_통                    ★모든 오차항이 소거된다
```

### 조건 — "자세를 안 바꾼다"

이 상쇄가 성립하려면 두 측정 사이에 **관절 자세가 거의 같아야** 한다.
그래서 들어올릴 때 **관절 이동(MoveJ)이 아니라 순수 Z축 직선이동(MoveL)** 을 쓴다.

```python
rq.pos = [0.0, 0.0, +100.0, 0.0, 0.0, 0.0]   # BASE 기준 X,Y 0 · Z만 +100mm
rq.ref = 0                                    # DR_BASE
rq.mode = 1                                   # 상대이동
```

100mm 수직 이동이면 관절 변화가 작아 중력보상 오차 변화도 무시할 수 있다.

> 📌 **왜 BASE 기준인가**: 툴이 아래를 보고 있어 **툴 Z축과 BASE Z축이 같은 방향**이다.
> 무게는 중력 방향(BASE Z)으로 걸리므로 BASE 기준 `Fz`가 곧 하중이다.

## 4. 측정 5단계 전체 흐름

무게 측정은 **뚜껑 닫기 시퀀스(`run_lid('close')`)의 뒷부분**에서 일어난다.
이미 뚜껑을 통에 체결해 놓은 상태이므로, 뚜껑을 잡고 들면 **통이 통째로** 딸려 올라온다.

```
① 뚜껑 체결 완료 (P22 안착 → P23 회전 잠금)
        │
        ▼  comp_off()  ← 순응제어 해제, 강체 복귀
② 그리퍼 110mm 활짝 개방      ← 무부하 확정
        │
        ▼  wait_fz_settle() → sample_fz()
   ★ Fz₀ (영점) 확보
        │
③ 뚜껑 재파지 (0mm / 10N)
        │   폭 20~105mm 검증 → 실패 시 중단
        ▼  wait_fz_settle()   ← 재파지 충격이 잦아들 때까지
④ +Z 100mm 수직 상승 (MoveL, 20mm/s)
        │
        ▼  wait_fz_settle() → sample_fz()
   ★ Fz₁ 확보
        │
        ▼
⑤ 무게 = |Fz₁ − Fz₀| / 9.81
        │
        ▼  −90mm 하강 → 그리퍼 개방 → 복귀
```

### 각 단계의 존재 이유

| 단계 | 왜 필요한가 |
|---|---|
| ① `comp_off()` | 순응제어가 켜져 있으면 **힘이 흡수되어** Fz가 실제 하중을 반영하지 않는다. 반드시 강체로 복귀 |
| ② **개방** 후 영점 | 아래 [9장](#9-설계-결정과-그-근거) 참조 — 가장 중요한 설계 결정 |
| ③ 재파지 + 폭 검증 | 뚜껑을 다시 잡지 못하면 들어올릴 때 통이 떨어진다. `20 ≤ 폭 ≤ 105mm` 로 확인 |
| ③ 후 안정 대기 | 재파지 순간의 충격 진동이 남은 채 들면 ④ 측정이 오염된다 |
| ④ 100mm / 20mm/s | 충분히 들어 통이 완전히 떠야 함. 느린 속도로 흔들림 최소화 |
| ⑤ −90mm 하강 | 들어올린 100mm보다 10mm 적게 내려 **바닥에 쿵 찧지 않게** 함 |

## 5. 계산식 전부

### 무게

$$
W_{\text{kg}} = \frac{\lvert F_{z1} - F_{z0} \rvert}{9.81}
$$

```python
weight = round(abs(fz1 - fz0) / 9.81, 3)      # kg, 소수 3자리
```

| 기호 | 의미 | 단위 |
|---|---|---|
| `Fz₀` | 들기 전 Z축 힘 (절사평균) | N |
| `Fz₁` | 들어올린 뒤 Z축 힘 (절사평균) | N |
| `9.81` | 중력가속도 | m/s² |
| `W` | 통 전체 무게 | kg |

> **절대값(`abs`)을 쓰는 이유**: 툴 방향·부호 규약에 따라 `Fz`가 음수로 나올 수 있다.
> 부호가 아니라 **크기 변화**가 곧 무게이므로 절대값이 안전하다.

### 절사평균 (Trimmed Mean)

정렬한 표본에서 상·하위 각 `trim` 비율을 잘라내고 평균한다.

$$
k = \lfloor n \cdot \text{trim} \rfloor, \qquad
\bar{x} = \frac{1}{n-2k}\sum_{i=k+1}^{n-k} x_{(i)}
$$

```python
def _trimmed_mean(vals, trim):
    v = sorted(x for x in vals if x is not None)
    if not v:
        return None, None
    k = int(len(v) * float(trim))
    core = v[k:len(v) - k] if len(v) - 2 * k >= 3 else v   # 남는 게 3개 미만이면 자르지 않음
    m = sum(core) / len(core)
    var = sum((x - m) ** 2 for x in core) / len(core)
    return m, var ** 0.5
```

`trim = 0.2` → **상·하위 20%씩 총 40% 제거**, 가운데 60%만 평균.

> ⚠️ **안전장치**: 자르고 남은 표본이 3개 미만이면 **자르지 않고 전체를 쓴다.**
> 표본이 적을 때 과도하게 잘라 평균이 무의미해지는 것을 막는다.

### 표준편차 (같은 core 구간에서)

$$
\sigma = \sqrt{\frac{1}{n_{\text{core}}}\sum_{i \in \text{core}} (x_i - \bar{x})^2}
$$

모표준편차(분모 `n`)를 쓴다. 표본이 15개 내외로 충분하고, 신뢰도 표시용이라 보수적일 필요가 없다.

### 안정 판정

최근 `N`개 표본의 표준편차가 임계 이하이면 "안정".

$$
\sigma_{\text{recent}} = \sqrt{\frac{1}{N}\sum_{i=1}^{N}(x_i - \bar{x})^2} \le \sigma_{\text{lim}}
$$

`N = 8`, `σ_lim = 0.35 N`

### 신뢰도 (측정 편차)

두 측정 구간의 표준편차를 **오차 전파 법칙**으로 합성한다.
`Fz₀`와 `Fz₁`은 독립 측정이므로 분산이 더해진다.

$$
\sigma_W = \frac{\sqrt{\sigma_0^{\,2} + \sigma_1^{\,2}}}{9.81}
$$

```python
w_sd = round(((sd0 or 0) ** 2 + (sd1 or 0) ** 2) ** 0.5 / 9.81, 3)   # kg
```

UI에는 **그램 단위 초록 글씨**로 표시한다:

```javascript
± ${Math.round(+wsd*1000)} g   측정 편차
```

## 6. 노이즈 억제 ① 적응형 안정 대기

### 문제 — 진자 운동

통은 **뚜껑 하나로 매달려** 있다. 들어올리면 **진자처럼 흔들린다.**

```
       그리퍼
         │
       뚜껑         ← 여기 한 점으로만 연결
      ╱  │  ╲
     │   통   │      ← 좌우로 흔들림 → Fz 가 주기적으로 요동
      ╲     ╱
```

**고정 시간 대기(예: `sleep(2)`)의 한계**: 흔들림이 얼마나 남을지는 매번 다르다.
빠르게 들었으면 많이 흔들리고, 통이 무거우면 오래 간다.
진동이 남은 채 측정하면 **측정마다 값이 튄다** — 이게 노이즈의 주원인이었다.

### 해결 — 실제로 잠잠해질 때까지 기다린다

```python
def wait_fz_settle():
    dt   = 0.1     # fz_sample_s   — 표본 간격
    need = 8       # fz_settle_n   — 판정에 쓰는 최근 표본 수
    lim  = 0.35    # fz_settle_std — 안정 임계 [N]
    tmax = 6.0     # fz_settle_max_s — 상한

    t0 = time.time(); buf = []
    while time.time() - t0 < tmax:
        chk()                          # 사용자 중단(■) 확인
        v = _read_fz()
        if v is not None:
            buf.append(v)
            if len(buf) > need:
                buf.pop(0)             # 슬라이딩 윈도우
            if len(buf) == need:
                m  = sum(buf) / need
                sd = (sum((x - m) ** 2 for x in buf) / need) ** 0.5
                if sd <= lim:
                    return time.time() - t0     # 안정까지 걸린 시간
        time.sleep(dt)
    return None                        # 상한 초과 — 흔들림이 안 잦아듦
```

**슬라이딩 윈도우** 방식이라 최근 0.8초(8×0.1s)만 본다. 과거 진동에 발목 잡히지 않는다.

### 어디에 쓰이나 — 3곳

| 위치 | 목적 |
|---|---|
| ② 영점 측정 직전 | 순응 해제 직후 잔진동 |
| ③ 재파지 직후 | 그리퍼가 무는 순간의 충격 |
| ④ 들어올린 직후 | **진자 운동** (가장 중요) |

## 7. 노이즈 억제 ② 절사평균

안정 판정을 통과해도 **순간적으로 튀는 값**은 남는다 (전기적 노이즈, 순간 진동).

```python
def sample_fz(sec=None):
    dt  = 0.1      # fz_sample_s
    win = 1.5      # fz_window_s — 측정 구간
    t0 = time.time(); vals = []
    while time.time() - t0 < win:
        chk()
        v = _read_fz()
        if v is not None:
            vals.append(v)
        time.sleep(dt)
    return _trimmed_mean(vals, 0.2)     # fz_trim
```

1.5초 동안 **약 15개** 표본을 모아 상·하위 20%를 자르고 평균한다.

### 왜 단순 평균이 아닌가

```
표본: [12.1, 12.0, 12.2, 12.1, 19.8, 12.0, 12.1, ...]
                                 ↑ 튄 값 하나

단순 평균 → 12.1 → 13.2  (한 개가 전체를 끌어올림)
절사평균  → 12.1        (정렬 후 양끝이 잘려 나감)
```

**중앙값보다 나은 점**: 중앙값은 표본 하나만 쓰지만, 절사평균은 가운데 60%를 다 써서
**노이즈 제거와 통계적 안정성을 동시에** 얻는다.

## 8. 신뢰도 산출

측정값만 주면 "이게 믿을 만한가"를 알 수 없다. 그래서 **±편차를 함께** 낸다.

```
Fz₀ 구간 σ₀ = 0.21 N
Fz₁ 구간 σ₁ = 0.28 N
──────────────────────
σ_W = √(0.21² + 0.28²) / 9.81 = 0.036 kg  →  ± 36 g
```

이 값이 크면(예: ±100g 이상) 흔들림이 덜 잦아든 것이므로 **측정을 신뢰하지 않는 게 맞다.**

추가로 `wait_fz_settle()`이 상한(6초)을 넘겨 `None`을 반환하면 **안정에 실패**한 것이므로
그 사실도 결과에 남긴다(`settle_s`).

### 반환 구조

```python
return {
    'status':    'ok',
    'weight_kg':  weight,     # 계산된 무게
    'weight_sd':  w_sd,       # ±kg
    'settle_s':   _settle,    # 안정까지 걸린 시간 (None이면 실패)
    'fz_before':  fz0,        # 원시값 — 디버깅용
    'fz_after':   fz1,
}
```

## 9. 설계 결정과 그 근거

### 🔑 결정 ① 영점은 "그리퍼를 열고" 잰다

이것이 정확도를 가장 크게 바꾼 결정이다.

```python
if cfg.GRIPPER.get('weight_tare_open', True):
    msg('🧢 ⑤ 영점 측정 — 그리퍼 개방(무부하)')
    grip_to(110, cfg.GRIPPER.get('lid_release_force', 15.0), 1.2)
    wait_fz_settle()
    fz0, sd0 = sample_fz()
    msg('🧢 ⑤b 뚜껑 재파지')
    _rw = grip_to(0, cfg.GRIPPER.get('weight_regrip_force', 10.0), 2.0)
    if _rw is None or not (20.0 <= _rw <= 105.0):
        raise RuntimeError(f'영점 후 뚜껑 재파지 실패(폭 {_rw}mm)')
```

**닫은 채로 영점을 재면 왜 안 되는가:**

뚜껑을 잡고 있으면 **뚜껑 하중의 일부가 이미 그리퍼에 걸린다.**
그 상태를 영점으로 삼으면 그만큼이 Δ에서 빠진다.

```
닫은 채 영점:  Fz₀' = 기준 + (뚜껑하중 × α)     ← α = 그리퍼에 걸린 비율
들어올린 뒤:   Fz₁  = 기준 + 통무게 + 뚜껑하중
Δ = 통무게 + 뚜껑하중 × (1 − α)                ← α 만큼 무게가 사라짐
```

**문제는 α가 매번 다르다는 것.** 파지 위치·힘·뚜껑 각도에 따라 달라져 무게가 튀었다.

→ **활짝 열면 α = 0** 으로 확정된다. 뚜껑은 이미 통에 **잠겨 있어** 열어도 떨어지지 않는다.

> 이 동작 하나로 측정 재현성이 크게 개선됐다.
> `weight_tare_open = False` 로 두면 예전 방식(닫은 채 측정)으로 돌아간다.

### 🔑 결정 ② 순응제어를 반드시 끄고 잰다

```python
finally:
    comp_off()      # 들어올리기 전 강체 복귀(무게 정확)
```

순응제어(compliance)는 **힘을 흡수하도록** 설계된 모드다.
켜진 채로 들면 로봇이 부드럽게 따라가며 힘을 흘려보내 **Fz가 실제 하중보다 작게** 나온다.

### 🔑 결정 ③ 모니터 스냅샷이 아니라 서비스를 직접 호출

```python
def _read_fz():
    """모니터 스냅샷은 사이클 중 폴링이 멈춰 동결되므로(ΔFz=0 버그) 서비스를 쓴다."""
    rq = ctx.GetToolForce.Request(); rq.ref = 0      # DR_BASE
    r = ctx.call(ctx.ctf, rq, cto=1.0)
    tf = getattr(r, 'tool_force', None) if r is not None else None
    tf = list(tf) if tf is not None else []           # ★numpy 진리값 평가 금지
    if len(tf) >= 3:
        return float(tf[2])
```

**실측 버그**: `RobotMonitor`는 모션 중에 폴링을 멈춘다(컨트롤러 부하 방지).
그래서 스냅샷을 읽으면 **Fz₀와 Fz₁이 같은 동결값**이 되어 **ΔFz = 0 → 무게 0kg** 이 나왔다.

→ 측정 시점에 **`GetToolForce` 서비스를 직접** 호출한다.

> ⚠️ **`tf = list(tf)` 가 중요한 이유**: `tool_force`가 numpy 배열로 오면
> `if tf:` 같은 진리값 평가에서 *"truth value of an array is ambiguous"* 예외가 난다.
> 반드시 리스트로 변환한 뒤 `len()`으로 검사한다.

### 🔑 결정 ④ 상대이동 재시도 시 "남은 거리만"

`movel_z`는 **상대이동(`mode=1`)** 이다. 외력 복구 후 그냥 재시도하면
멈춘 지점에서 **또 100mm**를 가서 총 이동이 늘어난다.

```python
def movel_z(dz_mm, vmm=20.0):
    """★상대이동(mode=1)이라 재시도하면 '멈춘 지점에서 다시 dz_mm'이 되어 총 이동이
      늘어난다. 그래서 복구 후에는 남은 거리만큼만 다시 간다."""
    moved = [0.0]
    def once():
        z0 = _cur_z()
        try:
            _movel_z_once(dz_mm - moved[0], vmm)     # 남은 거리만
        finally:
            z1 = _cur_z()
            if z0 is not None and z1 is not None:
                moved[0] += (z1 - z0)                # 실제로 간 거리 누적
        return True
    return trip.guarded(once)
```

실제 Z 좌표(`posx[2]`)로 **간 거리를 실측 누적**해서 남은 거리를 계산한다.
자세한 자동복구 구조는 [AUTO_RECOVERY.md](AUTO_RECOVERY.md) 참조.
